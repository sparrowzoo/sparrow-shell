Spring Boot 资源访问与 URL 映射说明

本页基于当前项目 demo/spring-boot-test 的 src/main/resources 目录， 以第三方中立视角说明 Spring Boot 的资源访问机制，覆盖三类处理逻辑： 静态资源、动态资源（@Controller）与 自动 Controller（addViewControllers 视图控制器）。 服务端口来自 application.properties 的 server.port=8888。

1. Spring Boot 默认静态资源位置（优先级从高到低）

spring-boot-starter-web 的自动配置 WebMvcAutoConfiguration 将 classpath: 下的以下目录映射为静态资源根，统一挂载到 /** （前缀由 spring.mvc.static-path-pattern 控制，默认 /**）：

  1. classpath:/META-INF/resources/ —— 优先级最高
  2. classpath:/resources/
  3. classpath:/static/
  4. classpath:/public/ —— 优先级最低

同名文件出现在多个目录时，按上述顺序先匹配者生效。 静态资源位置列表可通过 spring.web.resources.static-locations 覆盖。

2. webjars 资源位置

webjars 是「以 jar 包形式发布的 Web 前端资源」。Spring Boot 将 /webjars/** 路径 单独映射到 classpath:/META-INF/resources/webjars/， 因此依赖 jar 包内 META-INF/resources/webjars/ 下的资源可直接通过 /webjars/xxx 访问。

4. URL 映射与三类资源处理机制

一次 HTTP 请求进入 DispatcherServlet 后，会按 order 从小到大遍历所有 HandlerMapping，由第一个返回非空处理器的映射接管请求。Spring MVC 默认注册的映射链如下：

4.1 Spring MVC 默认 HandlerMapping 链

order HandlerMapping 负责内容
0 RequestMappingHandlerMapping 动态资源：@Controller / @RequestMapping / @GetMapping 等注解方法
1 ViewControllerHandlerMapping 自动 Controller：addViewControllers 注册的 URL → 视图
2 BeanNameUrlHandlerMapping 名字以 / 开头的 bean
MAX-1 ResourceHandlerMapping 静态资源：/webjars/** 与 /** → 静态目录
更低 WelcomePageHandlerMapping 欢迎页 index.html

优先级结论：动态资源 > 自动 Controller > 静态资源。 因此同一 URL 若同时存在 @Controller 与视图控制器，@Controller 优先； 若同时存在视图控制器与同名静态文件，视图控制器优先。

4.2 三类资源实现逻辑对比

资源类型 实现入口 处理逻辑 典型示例
动态资源 @Controller + @RequestMapping 由 RequestMappingHandlerMapping 命中，执行控制器方法；方法可访问 service/model，返回视图名或 @ResponseBody JSON @GetMapping("/user") 返回 JSON 或页面
自动 Controller addViewControllers 由 ViewControllerHandlerMapping 命中，跳过控制器方法，直接把 URL 当视图名交给 ViewResolver 渲染模板 /login → templates/login.html
静态资源 ResourceHandlerMapping 命中后由 ResourceHttpRequestHandler 在静态目录列表中按优先级查找文件，找到即返回原始字节 /index.html、/webjars/static.js

4.3 自动 Controller 实现逻辑

addViewControllers 将配置中的视图名逐个注册为 URL 映射，本质是「无控制器方法、纯跳模板」的快捷通道。 视图名交给 ViewResolver（如 Thymeleaf）后，由视图解析器用 prefix + viewName + suffix 拼出实际模板路径： 

registry.addViewController("/login").setViewName("/login");
// → ViewResolver → classpath:/templates/login.html

需要注意：视图名若带前导 /，Thymeleaf 会在拼接 prefix 前剥掉它， 因此最终路径仍是 classpath:/templates/login.html，而非 classpath:/templates//login.html。

5. 小结

  • 静态资源：由 ResourceHandlerMapping 按 META-INF/resources → resources → static → public 顺序查找，直接返回文件字节。
  • 动态资源：由 RequestMappingHandlerMapping 命中 @Controller，优先级最高，可执行任意业务逻辑。
  • 自动 Controller：由 ViewControllerHandlerMapping 命中，跳过控制器方法，URL 直接映射到模板视图，优先级介于动态与静态之间。
